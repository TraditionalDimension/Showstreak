# Additive API notes for Showstreak 1.3.0

API contract **1**, revision **1.1.0**. Read [initialization, ownership and base fields](API.md) first. Register during mod initialization, before `SMODS.booted`; retain provider namespaces, finite plain data, atlas/center validation and custom-effect versioning. Use the provider-bound facade for supported methods with dot calls. These examples are fragments to place inside a normal `showstreak_init` hook.

## Pack pools, capability 2

`Showstreak.get_api_info().capabilities.pack_pools` is **2**. New pools `vouchers` and `mixed` require `pack_version=2`. Existing `props` and `tricks` packs without a version retain their old receipt path and remain supported.

```lua
local info = Showstreak.get_api_info()
assert((info.capabilities.pack_pools or 0) >= 2)
assert(api.register_item{
    id = 'mymod_patron',
    kind = 'pack', effect = 'pack',
    pool = 'vouchers', pack_version = 2,
    price = 4, value = 2, choose = 1,
    art = 'p_arcana_normal_1',
})
```

The provider bound to `api` must have the namespace `mymod_` in this example. Supply localization as described in the base reference.

| Field | Version-2 rule |
| --- | --- |
| `kind`, `effect` | `pack`, `pack` |
| `pool` | `props`, `tricks`, `vouchers` or `mixed` |
| `price` | Integer 0–999, ordinary stars |
| `value` | Base offer count, integer 1–5 |
| `choose` | Integer 1–2, no greater than `value`; `vouchers` requires exactly 1 |
| `pack_version` | Exactly 2 |
| `pack_expandable` | Normalized to `true`; explicit `false` is rejected |
| `max_options` | Normalized to 6; an explicit different value is rejected |

Prop Master adds one offered option up to the cap, without increasing `choose`; a scarce pool is not padded with duplicates. Opening requires enough candidates for the base count. Pools use eligible entries from the campaign's frozen catalog, including compatible providers. They do not contain conditions, nested packs or duplicate item IDs.

Taking a Prop/Trick adds it to held inventory, taking a voucher activates it immediately, and taking a contract accepts that Bet. A full inventory blocks only consumables. The next choice rechecks current prerequisites, capacity and contracts; an unavailable selection consumes neither a choice nor currency. A pack opening is one purchase; its inner selections do not spend stars or free-purchase credits. Grand Bill obtained from a pack expands offered Bets immediately.

Version-2 mixed generation guarantees a paid-item option, or a compatible paid-item pair for two choices; it cannot sell only free Bets. Opened pack IDs and remaining choices persist without redrawing on UI refresh/resume. `c.pack.version`, receipt state and the `packs_v2` RNG stream are implementation details; integrations should not edit them.

## Starting additions: declared Joker occupancy

`api.register_start_addon` accepts the optional **`starting_joker_count`**. It is an integer from **0 through 999**, representing the conservative maximum number of starting Joker slots occupied by any selectable option in that category. Add it to the existing complete registration:

```lua
-- In a complete registration with the usual name, description and callbacks:
starting_joker_count = 0, -- explicitly grants no starting Jokers
```

The required callbacks and their signatures are unchanged. Invalid values return the `starting_joker_count` error and matching diagnostic field. Zero is known zero; an omitted value is unknown. The value is frozen with `start_addon_definitions` when a series is created. Registering a value later does not backfill an old series or change a resumed contract. Increase the add-on version when its grant/occupancy contract changes.

Blue Skittles and Red Brain need a capacity guarantee for their promised Joker. A selected category with unknown occupancy blocks that combination before spending the item. Selecting None remains safe, and ordinary play without a promised grant remains available. Declare a maximum, not an optimistic average, and include every Joker the category can introduce at the start.

## Bet difficulty and Reprise metadata

For a supported registered `contract`, `bet_tier='easy'`, `'normal'` or `'hard'` chooses its shop column. Omit the field when no authored classification is available: the offer appears under Other. Rendering keeps its original saved purchase index. This field does not alter effects, price or the two-Bet acceptance cap.

External Props/Tricks are eligible for Reprise only with **`copy_safe=true`**. Item-generating effects must declare **`generates_items=true`**, which excludes them even if the copy flag is true. `copy_safe=false` explicitly opts out. Reprise itself is excluded. A declaration means that obtaining another copy through the ordinary receipt path is safe; it must not bypass custom-effect resume tokens or perform a grant while being inspected.

## Action-policy sources

`capabilities.action_policy_sources=1` identifies the action-policy registry. The public global entry point is `Showstreak.register_action_policy_source`; declare the provider explicitly. It is initialization-only and follows the lower-case provider namespace rule. `version` is an integer 1–999999, default 1; `evaluate` is required.

```lua
assert(Showstreak.register_action_policy_source{
    id = 'mymod_shop_rules', provider = 'MyMod', version = 1,
    evaluate = function(context)
        -- Report this provider's active restrictions, not Showstreak's Bets.
        return {no_reroll = true}
    end,
})
```

The read-only context contains `deck`, `rules`, `next`, `conditions` and `owned`; tables are copied. The callback must be deterministic, side-effect-free and must not consume gameplay RNG. Return the restrictions of the provider's current setup:

- Boolean restriction flags: `no_skip`, `no_reroll`, `no_shop`, `no_packs`, `no_sell`, `no_discards`, `needle_bosses`, `boss_lock`, `exclusive_boss_schedule`.
- `commission`: finite number 0–1; combined policies retain the greater restriction.
- `skippable`, `ordinary_bosses`, `showdown_bosses`: `false` declares that the respective route does not exist.
- `banned_bosses`: a map of boss keys to booleans, for example `{bl_hook=true}`.
- `unknown={no_reroll=true}` marks uncertainty about a particular mechanic. `unknown=true`, a callback failure or an invalid result prevents unsupported guarantees for affected mechanics.

Provider/version metadata is frozen with the catalog. Missing or incompatible policy sources block continuation rather than silently change the contract. A native deck may declare the same data in `config.showstreak_action_policy`. Unrelated mod presence does not by itself disable every new item.

## Boundaries and verification

This appendix does not expose arbitrary `boss_program`, `bonus_effects`, `reward_by_stake`, `shop_credits` or native starting-grant token schemas as general registration APIs. They serve built-in content and validation. Use supported custom effects and their saved version/token contract for independent behavior; declare action policies where that behavior affects eligibility.

Test both integration load orders, a new series, an old frozen catalog, missing providers, rollback on rejected actions, process restart/resume and no double grants. Verify hover/catalog previews without RNG or mutations. Use isolated profiles for in-game checks. Baseline examples do not cover every new combination; [RELEASE_130](RELEASE_130.md) describes the release and editor boundaries.
