# Showstreak: руководство для авторов интеграций

**Showstreak 1.0.0 · API v1 · TraditionalDimension**

Практическое руководство по созданию собственного мода-провайдера: предметы, колоды, локализация, реплики Шоумена, сохранения и выпуск. Контракты сверены с реализацией версии 1.0.0. Английский справочник: [API.md](API.md). Учебный пример: [examples/integration](examples/integration/README.md).

Руководство описывает взаимодействие через API. Собственный мод распространяется отдельно и объявляет зависимость Showstreak. Файлы исполнения, оригинальные изображения, звук и сохранения Showstreak не включаются в архив интеграции. Условия использования определяет [LICENSE](../LICENSE); предоставление API не означает разрешения перепубликовывать весь мод или его ресурсы.

## 1. Что можно расширять

У API три точки регистрации: `register_item`, `register_deck` и `register_showman_reaction`. Первая добавляет данные предмета в каталог Showstreak, вторая описывает ресурсы уже существующей колоды, третья добавляет ситуативные реплики. `showman_event` сообщает собственное публичное событие. Диагностику дают `provider_manifest`, `mod_report` и `environment_report`.

| Задача | Поддерживаемый механизм |
|---|---|
| Предмет для подготовки следующего забега | `kind='prop'` и один поддерживаемый эффект |
| Мгновенное изменение выбора или условий | `kind='trick'` |
| Купон, действующий между забегами | `kind='voucher'` |
| Ставка с наградой за победу | `kind='contract'` |
| Набор предметов на выбор | `kind='pack'` |
| Собственная колода | Сначала обычный Back, затем `register_deck` |
| Реплика при покупке или собственном событии | `register_showman_reaction` |

API не регистрирует новые типы эффектов, произвольные игровые callbacks, семейства условий/масок, новые магазины, пользовательские pools наборов, платные контракты, миграции сохранений или настройки. Пресеты правил импортируются как JSON через меню; функции `register_preset` нет. Не добавляйте придуманные поля в надежде, что они реализуют поведение.

Часть доступных Lua-функций внутри `Showstreak` обслуживает сам мод. Наличие функции в таблице не превращает её в стабильный публичный контракт. Для интеграции держитесь перечисленных точек входа; внутренние `core`, `store`, UI-таблицы и сохранённый каталог нельзя редактировать в боевой логике.

## 2. Порядок загрузки и идентификаторы

Регистрация выполняется один раз при загрузке вашего мода: **после Showstreak, до `SMODS.booted`**. После boot регистраторы возвращают `nil, 'registration_closed'`. Не регистрируйте контент в update, кнопках, событиях покупки или при старте каждого забега.

Showstreak имеет приоритет `10000010`; Steamodded загружает меньшие значения раньше. У отдельного провайдера можно поставить `10000011` и зависимость версии 1.0.0. Сам Showstreak требует Steamodded 26.829.0+ и Lovely 0.9+; не вкладывайте эти загрузчики в интеграцию.

Для локального учебного запуска создайте `Mods/ShowstreakExample/` и поместите туда манифест:

```json
{
  "id": "ShowstreakExample",
  "name": "Showstreak Integration Example",
  "author": ["Your name"],
  "description": "A local Showstreak API tutorial.",
  "prefix": "sse",
  "main_file": "main.lua",
  "version": "1.0.0",
  "priority": 10000011,
  "dependencies": ["Showstreak (>=1.0.0)"]
}
```

Имя файла: `ShowstreakExample.json`. Соседний `main.lua` приведён в следующем разделе. Готовая локальная версия обоих файлов есть в `examples/integration`; для учебного запуска уберите суффикс `.example`. В папке исходного Showstreak эти файлы остаются неактивными.

**Три разных пространства имён:**

| Значение | Пример | Для чего |
|---|---|---|
| ID мода | `ShowstreakExample` | provider, dependency и начало своего события |
| Prefix Steamodded | `sse` | Обычные центры/атласы SMODS: например `b_sse_reserve` |
| Namespace Showstreak | `showstreakexample_` | ID предметов, семейств и реакций |

Namespace получается из ID провайдера: нижний регистр, знаки кроме букв/цифр/подчёркивания заменяются на `_`, затем добавляется `_`. Полный ID предмета и реакции должен соответствовать `^[a-z][a-z0-9_]*$`. `Other-Mod` и `Other_Mod` дают одинаковый префикс; коллизии пространства имён предметов отклоняются. Для публикуемого мода выберите собственный устойчивый ID.

`provider` обычно не указывается: регистратор использует `SMODS.current_mod.id`. Явный provider нужен лишь при осознанной регистрации от имени другого доступного мода. Не присваивайте чужой namespace.

## 3. Рабочий минимальный main.lua

Этот вариант использует нативное оформление, поэтому дополнительные PNG и звуки не нужны. Вставьте его в отдельный учебный мод из раздела 2. Это альтернативный минимальный файл; готовый пример на диске дополнительно содержит купон.

```lua
local S = assert(Showstreak, 'Showstreak must load first')
assert(S.api and S.api.version == 1, 'Expected API v1')

local id, reason = S.register_item{
    id = 'showstreakexample_spare_hand',
    kind = 'prop', effect = 'hands', value = 1,
    price = 2, art = 'j_joker', content_version = 1,
    loc_txt = {
        ['en-us'] = {
            name = 'Spare Hand',
            text = {'{C:blue}+#1#{} hand each round',
                    'during the next run'},
        },
        ru = {
            name = 'Запасная рука',
            text = {'{C:blue}+#1#{} рука каждый раунд',
                    'в следующем забеге'},
        },
    },
}
assert(id, tostring(reason))

local reaction, why = S.register_showman_reaction{
    id = 'showstreakexample_spare_hand_bought',
    event = 'buy',
    match = {item_id = id, source = 'buy'},
    priority = 60,
    text = {
        ['en-us'] = {'An extra hand. A useful precaution.'},
        ru = {'Лишняя рука. Полезная предосторожность.'},
    },
}
assert(reaction, tostring(why))
```

После полного перезапуска провайдер должен появиться в отчёте модов как интегрированный. **Создайте новую серию:** существующая сохраняет прежний каталог. Предложение случайно, поэтому отсутствие предмета в первом магазине само по себе не говорит об ошибке.

Ожидаемая последовательность: купить предмет за 2 звезды, увидеть его в инвентаре, применить кнопкой Use, начать следующий забег. Покупка сама по себе не даёт дополнительную руку. После Use прибавка действует в каждом раунде следующего забега; возобновление сохранения не должно применять её повторно.

Если регистрация вернула ошибку, останавливайте загрузку учебного мода с понятной диагностикой. В готовой интеграции можно обработать отказ иначе, но молча считать регистрацию успешной нельзя.

## 4. Контракт предмета

`Showstreak.register_item(def)` возвращает ID при успехе либо `nil, reason`. Определение копируется. Допустимы простые данные: строки, логические значения, конечные числа и таблицы без метатаблиц/циклов. Функции, userdata, NaN и бесконечности отклоняются даже внутри дополнительной вложенной таблицы.

| Поле | Требование |
|---|---|
| `id` | Уникальный ID в namespace провайдера |
| `provider` | Необязательный ID; по умолчанию текущий мод |
| `kind`, `effect`, `value` | Обязательная совместимая комбинация из раздела 5 |
| `price` | Целое 0..999 звёзд; для contract только 0 |
| `art` | Ключ известного центра; например `j_joker` или `v_seed_money` |
| `atlas`, `pos` | Альтернатива art: известный atlas и целые x/y 0..9999 |
| `loc_txt` | Описание Steamodded; желательно полноценное EN и RU |
| `weight` | Необязательное целое 1..100; значение по умолчанию 1 |
| `family` | Необязательный ID группы в том же namespace |
| `family_weight` | Целое 1..100; одинаковое у всех членов семьи, default 1 |
| `requires` | Только voucher; ID уже зарегистрированного voucher-родителя |
| `reward` | Для contract обязательно 0..999; допустимо также у trick/ante |
| `max_once` | Необязательный boolean только у trick/ante |
| `deck` | Только set_deck; существующая поддерживаемая колода |
| `pool`, `choose` | Только pack; pool props/tricks, choose от 1 до value |
| `content_version` | Целое 1..999999, default 1; метаданные |

Если указаны и `atlas`, и `art`, используется явный atlas. Позиция задаётся в ячейках, а не пикселях. Ошибку размеров реального PNG регистратор не гарантирует обнаружить.

`activation`, `lifetime` и `visual` назначаются самим API по kind. Их не следует задавать как способ изменить семантику. Регистратор предметов не является универсальной строгой схемой для всех неизвестных ключей: простое дополнительное поле может быть скопировано, но никакого нового поведения это не создаёт.

При ошибке нативной регистрации центра каталог не пополняется, возвращается `center`; подробность доступна в `Showstreak.api.last_error`. Исправляйте исходное определение, а не дописывайте вручную `Showstreak.content.items` или `order`.

## 5. Эффекты и срок действия

Девять ресурсных эффектов: `money`, `hands`, `discards`, `hand_size`, `joker_slots`, `consumable_slots`, `deck_size`, `shop_slots`, `booster_slots`. Значение -999..999, целое. Это изменение соответствующего ресурса, а не абсолютное итоговое значение.

Эффекты `blind`, `boss`, `prices` принимают конечные дробные изменения. `0.15` означает +15%, `-0.20` означает -20%. Вклады в один модификатор складываются: +0.15 и -0.05 дают +0.10. Коэффициент очков серии применяется отдельно. Валидатор не оценивает баланс и не обещает разумный результат крайних процентов.

| Kind | Эффекты | Что происходит |
|---|---|---|
| `prop` | Ресурсы, blind/boss/prices | Buy/Take кладёт в инвентарь; Use готовит эффект для следующего забега |
| `contract` | Ресурсы, blind/boss/prices | Бесплатное принятие сразу готовит эффект; победа даёт reward |
| `voucher` | Всё выше плюс reward, held_slots, reveal_act, free_reroll | Покупка активирует до принятого Антракта или конца серии |
| `trick` | reveal, reveal_all, deck, set_deck, stake, ante, remask, remove_condition | Buy/Take кладёт в инвентарь; Use выполняет мгновенное действие |
| `pack` | Только pack | Покупка открывает выбор; выбранные предметы идут в инвентарь |

Фиксированное `value=1` требуется для reveal, reveal_all, reveal_act, deck, set_deck, remask и remove_condition. Для stake требуется `-1`. Для ante - ненулевое целое от -15 до 15. Voucher-эффекты reward, held_slots, free_reroll требуют положительное целое до 999. Pack: value 1..5; choose не превышает value.

`deck` перевыбирает колоду по правилам; `set_deck` назначает конкретную. Последний доступен только если целевая колода включена в список серии и отличается от следующей выбранной. Он сохраняет seed следующего забега и не берёт дополнительную колоду из мешка.

Контракт не может иметь платную цену. `reward` у контракта означает звёзды за победу, а не предметы, доллары или Dark Stars. У voucher/`effect='reward'` величина бонуса задаётся через value, а не через поле reward.

Антракт очищает купоны, инвентарь, накопленные условия и подготовку; сохраняет общую серию побед, Dark Stars, замороженные правила и каталог. Поэтому описание «навсегда» для купона неверно.

## 6. Готовые схемы расширения

Следующий блок можно добавить к `main.lua` из раздела 3. Он использует тот же provider и отдельные ID. Родительский купон регистрируется раньше улучшения; цена задана у каждого предмета явно.

```lua
local S = assert(Showstreak)
local function add(def)
    local id, why = S.register_item(def)
    assert(id, tostring(why))
end
add{
    id = 'showstreakexample_budget', kind = 'voucher',
    effect = 'money', value = 2, price = 3,
    art = 'v_seed_money',
    loc_txt = {name = 'Budget', text = {'Start with +$#1#'}},
}
add{
    id = 'showstreakexample_budget_plus', kind = 'voucher',
    effect = 'money', value = 3, price = 5,
    requires = 'showstreakexample_budget', art = 'v_seed_money',
    loc_txt = {name = 'More Budget', text = {'Start with +$#1#'}},
}
add{
    id = 'showstreakexample_risk', kind = 'contract',
    effect = 'blind', value = 0.15, price = 0, reward = 4,
    art = 'j_joker',
    loc_txt = {name = 'Risk', text = {'Higher blinds',
                                    'Win to earn #2# Stars'}},
}
add{
    id = 'showstreakexample_low_stake', kind = 'trick',
    effect = 'stake', value = -1, price = 3, art = 'c_world',
    family = 'showstreakexample_tickets', family_weight = 1,
    loc_txt = {name = 'Lower Stake', text = {'Lower next stake'}},
}
add{
    id = 'showstreakexample_case', kind = 'pack', effect = 'pack',
    value = 3, choose = 1, pool = 'props', price = 3,
    art = 'p_arcana_normal_1',
    loc_txt = {name = 'Case', text = {'Choose #2# of #1# items'}},
}
```

Купоны родителя и улучшения складываются: после покупки обоих бонус денег равен +5. `requires` управляет доступностью улучшения; это не декларация автоматической замены родителя.

Семья получает один вес как группа, затем внутри неё применяется вес участника. Десять билетов в одной семье не должны занимать десятикратную долю магазина. Все члены обязаны иметь одинаковый family_weight. Обычный weight отдельного предмета и family_weight решают разные задачи.

Pool `props` включает props и tricks, pool `tricks` - только tricks. API не поддерживает массив собственных ID вместо pool. В одном открытом наборе ID не повторяются. Пригодность предметов проверяется до выбора.

## 7. Тексты и собственные изображения

Созданный центр находится в наборе описаний `Showstreak`, ключ: `sstreak_item_<полный ID>`. У примера это `sstreak_item_showstreakexample_spare_hand`. Можно передавать языки прямо в loc_txt, как в разделе 3, или добавлять их через обычные localization-файлы своего мода. EN в самом loc_txt полезен для восстановления старого предмета из сохранения.

Переменные описания: `#1#` - value; `#2#` - reward или число выбираемых предметов пакета; `#3#` - значение с суммой цепочки prerequisites. Для blind/boss/prices `#1#` содержит локализованные слова точного отношения, например «одна пятая», а не автоматически число процентов. Пишите фразу под такую подстановку. В loc_txt допустимо форматирование Balatro, например `{C:blue}`; в репликах Шоумена такие фигурные скобки запрещены.

Для собственного PNG сначала зарегистрируйте атлас, затем предмет. Этот дополнительный пример **требует подготовленных вами файлов** `assets/1x/my_cards.png` и `assets/2x/my_cards.png` в моде-провайдере. Ячейка 71x95 и 142x190 соответственно; pos ниже выбирает первую ячейку. Готовый базовый пример PNG не требует.

```lua
local S = assert(Showstreak)
SMODS.Atlas{
    key = 'showstreakexample_cards',
    prefix_config = {key = false},
    path = 'my_cards.png', px = 71, py = 95,
}
local id, why = S.register_item{
    id = 'showstreakexample_custom_art',
    kind = 'prop', effect = 'hands', value = 1, price = 2,
    atlas = 'showstreakexample_cards', pos = {x = 0, y = 0},
    loc_txt = {name = 'Custom Prop', text = {'+#1# hand'}},
}
assert(id, tostring(why))
```

Уникальное полное имя атласа выбрано явно через prefix_config: его же передаём в register_item. При стандартном префиксе Steamodded используйте реально зарегистрированный ключ, а не предполагайте его по имени PNG.

`art` переиспользует только статические atlas/pos существующего центра. Анимация, шейдеры и его игровой calculate не наследуются. Регистрация до инъекции G.P_CENTERS допустима, если центр уже есть в SMODS.Centers. При отсутствии текстуры после обновления восстановленный предмет может получить нативную картинку; эффект остаётся из сохранения.

Проверяйте оба масштаба, длинные переводы, tooltip и смену языка. Цвет текста, изображение и звуковая реакция не должны сообщать ложный срок действия предмета.

## 8. Адаптер обычной колоды

Адаптер **не создаёт Back и не выполняет его эффект**. Он сообщает Showstreak исходные ресурсы колоды для расчётов и предварительного отбора. Сначала зарегистрируйте обычную колоду через Steamodded, затем её адаптер. Ниже учебная колода с +2 руками; она использует нативный atlas centers, без нового PNG.

```lua
local S = assert(Showstreak)
SMODS.Back{
    key = 'reserve',
    pos = {x = 0, y = 0},
    config = {hands = 2},
    unlocked = true, discovered = true,
    loc_txt = {name = 'Reserve Deck',
               text = {'Start with {C:blue}+2{} hands'}},
}
local key, why = S.register_deck{
    key = 'b_sse_reserve', version = 1,
    baseline = {
        money = 4, hands = 6, discards = 3, hand_size = 8,
        joker_slots = 5, consumable_slots = 2, deck_size = 52,
        shop_slots = 2, booster_slots = 2,
    },
}
assert(key, tostring(why))
```

Этот блок рассчитан на manifest prefix `sse`. Для своего prefix измените key адаптера. Не используйте тот же Back key в двух модах. Добавьте учебную колоду при создании **новой** серии; наличие адаптера не делает её частью уже сохранённого списка.

Baseline должен содержать **ровно девять ресурсов** из раздела 5, без ante. Деньги: целое -999..999; остальные ресурсы: целое 0..999. Отсутствующий, лишний или неверно типизированный ресурс приводит к отказу. Ключ должен относиться к существующему Back, начинаться с `b_` и не иметь уже зарегистрированного адаптера. Version: 1..999999, по умолчанию 1.

Статический baseline описывает колоду при заводских стартовых настройках, до эффектов ставки. Для явных пользовательских стартовых значений Showstreak добавляет разницу с заводским значением. В примере: default hands 4, колода +2, baseline 6. Если игрок поставил base hands 7, итог перед ставкой равен 9.

Изменение состава стартовых карт должно соответствовать реальному Back. Baseline deck_size сам не реализует масти, ранги и специальные правила вашей колоды. Просмотр и фактический старт должны совпадать.

## 9. Вычисляемый baseline и именной билет

Вместо статической таблицы register_deck принимает функцию baseline. Это исключение из правила «только данные» предметов. Функция получает копию rules и возвращает **окончательные ресурсы до ставки**, уже с учётом настроек игрока. Showstreak не добавляет стартовую разницу второй раз.

Альтернатива статической регистрации из раздела 8 (не запускайте обе для одного key):

```lua
local S = assert(Showstreak)
local key, why = S.register_deck{
    key = 'b_sse_reserve', version = 1,
    baseline = function(rules)
        local s = rules and rules.version == 2 and rules.start
        if not s then
            s = {money = 4, hands = 4, discards = 3,
                 hand_size = 8, joker_slots = 5,
                 consumable_slots = 2, deck_size = 52,
                 shop_slots = 2, booster_slots = 2}
        end
        return {
            money = s.money, hands = s.hands + 2,
            discards = s.discards, hand_size = s.hand_size,
            joker_slots = s.joker_slots,
            consumable_slots = s.consumable_slots,
            deck_size = s.deck_size, shop_slots = s.shop_slots,
            booster_slots = s.booster_slots,
        }
    end,
}
assert(key, tostring(why))
```

Callback - доверенный код вашего мода. Он может вызываться для предварительного просмотра; не используйте RNG, сетевые запросы, запись сохранений и изменение глобального состояния. Возвращаемая таблица проверяется при использовании; неполный результат вызывает диагностику с именем провайдера/колоды. Успешная регистрация ещё не доказывает корректность всех ответов callback.

После любого из адаптеров можно добавить билет:

```lua
local id, why = Showstreak.register_item{
    id = 'showstreakexample_reserve_ticket', kind = 'trick',
    effect = 'set_deck', value = 1, deck = 'b_sse_reserve',
    price = 3, art = 'c_world',
    family = 'showstreakexample_tickets', family_weight = 1,
    loc_txt = {name = 'Reserve Ticket',
               text = {'Use Reserve Deck for the next run'}},
}
assert(id, tostring(why))
```

## 10. Реплики Шоумена

Регистрация принимает только `provider`, `id`, `event`, `match`, `priority`, `once`, `text`. Неизвестное поле отклоняется с `field`. Поля presentation, animation, calculate, sprite и собственные callbacks здесь не поддерживаются: выражение и переход в idle выбирает контроллер Showstreak.

`text['en-us']` обязателен. Каждый язык содержит массив из 1..4 строк общей длиной до 140 UTF-8 codepoints. В строках нельзя использовать `{`, `}`, CR или LF. Несколько исходных строк соединяются в одну реплику и заново переносятся; это не четыре обязательные экранные строки.

Текущий renderer измеряет ширину текста, целится в пять экранных строк при ширине 2.72 и уменьшает scale с 0.30 до 0.24. При минимальном размере он сохраняет слова даже при превышении целевого числа строк. Поэтому тестируйте самые длинные имена/подстановки и сокращайте текст сами, не рассчитывая на автоматическое многоточие.

Приоритет: целое 1..90, default 50. Более высокий приоритет помогает выбрать вашу подходящую реакцию, но история повторов и контекст тоже влияют. `once=true` означает один раз на профиль: память появляется, когда реакция выбрана для видимого экрана. Простая отправка события не гарантирует, что игрок увидит текст.

Языковой fallback внешней реплики проверяет запрошенный код, нормализованный код, базовый язык, язык игры, default и en-us. Поддерживаемые игровые коды: `en-us`, `ru`, `de`, `es_419`, `es_ES`, `fr`, `id`, `it`, `ja`, `ko`, `nl`, `pl`, `pt_BR`, `zh_CN`, `zh_TW`. Сохраняйте регистр и написание файлов на системах с чувствительностью к регистру.

`match` задаёт точные сравнения публичных полей. Разрешены строки, boolean и конечные числа. Поле, которого нет в событии, не совпадает. Контекст серии может заменить переданные stars/deck/stake актуальными значениями.

| Группа | Поля для match и подстановок |
|---|---|
| Предмет/действие | item_id, source, effect, kind, lifetime, value, reward, price |
| Серия/магазин | stars, free_slots, deck, stake, ante, cost, rerolls, remaining |
| Нативная игра | native_key, native_set, native_action |
| Результат | wins, reason, amount, dark_amount, has_active, record, act_reward, won_bet |

`#item_name#`, `#deck_name#`, `#native_name#` - дополнительные локализованные **выводимые** имена; это не поля match. Неизвестная/отсутствующая подстановка становится `?`. Входные строки очищаются и сокращаются до 160 codepoints; числовые значения должны быть конечными (NaN и бесконечности не принимаются). Не передавайте скрытые маски, будущие предложения или иной ещё не показанный игроку результат.

## 11. События и настройки игрока

Встроенные успешные действия включают buy, voucher, contract, pack, take, use, reveal, remask и mask. `intermission` сообщает принятый Антракт. У Showstreak-карточек source различает buy, held, pack и mask. Для предмета-подготовки покупка и Use - разные события. Не отправляйте вручную второе buy поверх события, которое Showstreak уже сформировал.

Собственное событие при регистрации должно начинаться с точного ID провайдера и двоеточия: `ShowstreakExample:encore`. Допустимые символы имени: буквы/цифры, `_`, `:`, `-`. ID самой реакции по-прежнему использует `showstreakexample_`.

```lua
local S = assert(Showstreak)
local id, why = S.register_showman_reaction{
    id = 'showstreakexample_encore',
    event = 'ShowstreakExample:encore',
    match = {source = 'encore'}, priority = 60, once = false,
    text = {
        ['en-us'] = {'An encore worth #amount# Stars.'},
        ru = {'Выход на бис принёс #amount# звезды.'},
    },
}
assert(id, tostring(why))
```

После успешного действия своего мода сообщите о **реальном** результате:

```lua
-- Only after your own action has actually succeeded:
Showstreak.showman_event('ShowstreakExample:encore', {
    source = 'encore', amount = 2,
})
```

Эта строка сама не начисляет две звезды, не проводит транзакцию и не открывает экран: она просит о презентации события. Не вызывайте её каждый кадр и не помещайте в startup как обещание, что игрок сразу увидит реплику. Контекст, настройки и правила повторов определят фактическое отображение.

У игрока независимые параметры quips, voice, effect_sounds и reduced_motion. Нельзя включать их принудительно ради интеграции. При отключённом голосе визуальная реакция может работать; при отключённых репликах доставка текста не обещается. Случайность Шоумена отделена от игровой случайности.

Отдельный существующий helper `Showstreak.visuals.configure_host_sprites` меняет карту кадров для новых портретов, но не относится к регистраторам API v1 и не предоставляет автору реакции контроль конкретного кадра. Для обычного провайдера он не нужен. Переопределение глобального облика требует отдельной сверки с текущим визуальным контроллером; API реакции не должен использовать его как скрытый callback.

## 12. Сохранения и обновления провайдера

Новая серия копирует правила, определения предметов и условий, порядок каталога и сведения о провайдерах. Это замороженный набор. Изменения новой версии интеграции применяются к новым сериям; старую серию нельзя «обновить» простой заменой value в живом каталоге.

Обязательными считаются провайдеры, представленные в сохранённом каталоге и включённых колодах, **а не только авторы купленных предметов**. Если такой провайдер исчез, продолжение блокируется с объяснением. Просто оставить папку мода, удалив всю регистрацию, недостаточно для прежней возможности интеграции.

| Обновление | Что ожидать |
|---|---|
| Добавить новый предмет | Появится в новых сериях |
| Изменить value существующего ID | Новые серии получают новое значение; старые используют сохранённое |
| Убрать ID, сохранив провайдера | Старое определение может восстановиться при показе карточки |
| Удалить требуемый мод | Продолжение блокируется |
| Поменять лишь номер версии/картинку | Это не автоматический отказ и не гарантия совместимости |
| Изменить нативный Back или сторонние hooks | Ответственность автора; frozen data не замораживает Lua-код |

Для удалённого живого ID Showstreak восстанавливает центр из сохранённого определения. Текущие переводы провайдера имеют приоритет; loc_txt из сохранения даёт запасной вариант. Текстуры и код в сохранение не встроены. При недоступной графике используется нативное оформление без изменения сохранённого эффекта.

Сохраняйте публичные ID, если смысл предмета прежний. Для радикально другого смысла разумнее новый ID, не подменяющий старый в чужих сохранениях. `content_version` предмета и `version` адаптера - метаданные, а не автоматические миграторы. Public migrate/register_migration нет. Не редактируйте чужие *.jkr и номер схемы, чтобы обойти диагностику.

Антракт сохраняет замороженный каталог; принятие Антракта не загружает предметы новой версии провайдера. Политики старых серий также не дополняются новым контентом молча.

Перед выпуском обновления тестируйте существующее сохранение с купленным/удалённым предметом, EN/RU, restart и временно отключённым провайдером. Полезно оставлять проверяемую совместимую регистрацию, пока игроки могут продолжать серии из предыдущих версий.

## 13. Диагностика и типичные ошибки

Регистраторы возвращают **две величины**. Используйте `local id, why = ...`; сообщение одной лишь функции assert без reason скрывает причину. Для ошибки center читайте `S.api.last_error`.

| Причина | Что проверить |
|---|---|
| registration_closed | Вызов выполняется после boot; перенесите в загрузку мода |
| data_only | Есть функция, metatable, цикл, userdata, NaN или infinity |
| provider | Неверный ID или мод недоступен |
| id / namespace | Перепутаны ID мода, SMODS prefix и namespace предмета |
| duplicate | ID/адаптер уже зарегистрирован; код вызван дважды |
| kind_effect / value | Несовместимая пара, неправильный тип или фиксированное значение |
| price / reward | Не задана цена, платный contract или отсутствует его reward |
| requires | Родитель не voucher, ещё не зарегистрирован или ссылается на себя |
| art / atlas | Центр/атлас отсутствует, pos нецелый или неправильный ключ |
| deck / deck_adapter / baseline | Back отсутствует, адаптера нет или неполны девять ресурсов |
| family / family_weight / weight | Чужой namespace, разные веса группы, значение вне 1..100 |
| pack | Неподдерживаемый pool, value вне 1..5 или choose больше value |
| text / match / event / field | Неверная реплика, закрытое поле данных, имя события или неизвестное поле |
| version / content_version | Неверное целое значение соответствующей версии |

`provider_manifest()` возвращает копии таблиц providers и mods. У провайдера есть version и capabilities: items, decks, showman. `mod_report()` содержит id, name, version, loaded, integrated, capabilities, changed и missing. `environment_report()` отдельно перечисляет игру и загрузчики. Это диагностика, а не разрешение редактировать их внутреннее состояние.

**Предмет не появился:** сначала проверьте успешный возврат регистрации, затем новую серию, требования родительского купона, доступность колоды/эффекта и случайную выдачу магазина. Успешная регистрация не означает гарантированное предложение.

**Предмет куплен, эффекта нет:** prop требует Use; voucher/contract активируются при покупке/принятии; trick действует сразу при Use. Сравнивайте итог с ресурсами выбранной колоды и ставки.

**Реплика не звучит:** разберите text/match, once на данном профиле, настройки игрока и актуальный экран. showman_event не гарантирует прерывание текущей реплики. **Серия не продолжает работу:** смотрите missing provider и наличие требуемых колод, не стирайте сохранения для маскировки проблемы.

## 14. Проверка перед выпуском

Сначала прогоните синтаксис Lua и контрактные тесты на исходниках. Player ZIP не обязан содержать tests. В исходном дереве Showstreak runner можно вызвать, указав LuaJIT DLL вашей Windows-установки игры:

```text
python Mods/Showstreak/tests/run_tests.py <path-to-lua51.dll>
```

Этот runner использует Windows DLL и читает соответствующий Balatro.exe. Это инструмент разработки, не инструкция устанавливать Python игрокам. Проверенные примеры этого руководства отдельно исполнялись против реальных функций API с макетом окружения; такой тест не заменяет графическую игру.

| Проверка | Ожидаемый результат |
|---|---|
| Чистый запуск | Нет ошибок загрузки, provider интегрирован |
| Новая серия | Ваши элементы входят в сохранённый каталог |
| Buy/Use/Take | Верный момент активации и цена; нет эффекта от неуспешного действия |
| Контракт | Награда за победу начисляется один раз |
| Voucher chain | Родитель открывает улучшение; эффекты складываются |
| Колода | Preview и старт совпадают при default/custom rules и stakes |
| Save/restart | Ресурсы не применяются повторно, каталог сохраняется |
| Старое сохранение | Изменённый/удалённый ID использует замороженное определение |
| Нет провайдера | Продолжение корректно заблокировано с причиной |
| UI и ввод | Tooltip, языки, 1x/2x, мышь и геймпад читаемы |
| Шоумен | Нет повторной спам-доставки, учтены voice/quips/reduced motion |
| Пакет файлов | Одна папка провайдера; нет чужих runtime/сохранений/QA |

Проверяйте покупку и отказ при недостатке звёзд, заполненном инвентаре и устаревшем подтверждении. Для deck callback используйте минимальные, стандартные и максимальные разрешённые настройки и случай rules=nil. Для текста - длинные имена и отсутствие необязательного поля.

Тестовый профиль защищает обычную игровую историю, но не является отдельной sandbox для всего кода модов. Работайте с резервной копией тестовых сохранений и не запускайте отладочные setters на основном профиле. Не меняйте игровой RNG ради демонстрации предмета в публичной сборке.

Метка «интегрирован» означает зарегистрированную возможность API. Она не гарантирует совместимость всех сторонних hooks, баланс или работу любых сочетаний модов.

## 15. Упаковка собственного мода

Свой ZIP должен содержать одну папку с вашим manifest, main.lua, собственными scripts/assets/localization, пользовательской инструкцией и условиями использования вашего кода/ресурсов. В dependency укажите Showstreak >=1.0.0 или более позднюю минимальную версию, которую действительно требует интеграция. Зафиксируйте точный проверенный набор игры/загрузчиков в описании выпуска.

Не вкладывайте Showstreak, Balatro, Steamodded, Lovely, оригинальные ресурсы Showstreak, config/Showstreak.jkr, пользовательские пресеты, *.jkr, тестовые профили, dumps и QA-скрипты. Игрок устанавливает Showstreak отдельно. LICENSE разрешает независимо написанные интеграции; учебные примеры и документация предназначены для изучения и локального тестирования, без разрешения на перепубликацию. Для распространения копий примеров или иных файлов Showstreak требуется отдельное разрешение автора.

Перед публикацией распакуйте **собственный финальный ZIP** в тестовое окружение и повторите минимальную цепочку: загрузка, новая серия, предмет, Use, старт, сохранение, restart. Проверка рабочей папки разработчика не обнаружит PNG или модуль, забытый в архиве.

Опишите игроку, что удаление провайдера может заблокировать продолжение серий, каталог которых содержит его предметы. Не обещайте свободное удаление посреди серии. Для обновления сообщите, какие изменения относятся только к новым сериям.

## 16. Где проверять контракт

Главный справочник поставки: [API.md](API.md). Учебный провайдер: [examples/integration/README.md](examples/integration/README.md). Эти материалы описывают Showstreak 1.0.0 и API v1.

Первичные источники реализации:

- `scripts/integration/api.lua`: регистрация, пределы значений, artwork, семьи, адаптеры и отчёты.
- `scripts/showman/showman.lua`: допустимые поля реакций, event/match/text, подстановки, повторения и публичная доставка.
- `scripts/localization/locale.lua`, `localization.lua`, `text.lua`: fallback, переменные описаний и перенос текста.
- `scripts/ui/cards.lua`: создание и восстановление центров из сохранённого каталога.
- `scripts/integration/integration.lua`: применённые ресурсы, baseline, provider manifests и проверка продолжения.
- `scripts/core/core.lua`: детерминированный каталог, предметы, пакеты, купоны, контракты и Антракт.

В исходной версии проекта дополнительные проверки находятся в `tests/api_v5_spec.lua`, `api_restore_v7_spec.lua`, `showman_v7_spec.lua`, `presets_v5_spec.lua` и тестах сохранения/интермиссии. Суффиксы v5/v7 указывают этап появления тестов, а не требуемую версию публичного API.

Это руководство не добавляет новых механизмов поверх исходников. Если нужное расширение отсутствует в перечисленном контракте, сначала согласуйте и реализуйте новую возможность API, затем документируйте её и изменяйте требуемую версию своего провайдера.
