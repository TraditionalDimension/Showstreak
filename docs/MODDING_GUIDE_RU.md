# Создание интеграции с Showstreak

Читайте вместе с [API.md](API.md), [подробностями API для 1.3.0](API_130.md) и [примечаниями о совместимости](RELEASE_130.md). PDF остаётся историческим руководством по API 1.1.0; этот Markdown учитывает поведение Showstreak 1.3.0.

**Руководство для моддеров · Showstreak 1.3.0 · контракт API 1, ревизия 1.1.0**  
TraditionalDimension

Загрузка, запуск самостоятельного редактора комиксов и работа с проектами:
[Toolkit и Lore Workshop](TOOLKIT.md#по-русски). Обычный лор игрока пока в разработке.

### Что добавлено для авторов в 1.3.0

- Проверяйте `get_api_info().capabilities`: ревизия API осталась 1.1.0.
  `pack_pools=2` добавляет поддерживаемые паки ваучеров и смешанного содержимого;
  `action_policy_sources=1` позволяет объявлять ограничения действий и боссов.
- Для внешнего пари задавайте авторскую сложность `bet_tier` либо оставляйте
  колонку Other. Безопасный расходник допускается к Reprise через `copy_safe=true`;
  создающие предметы эффекты исключаются через `generates_items=true`.
- В стартовой категории объявляйте максимум `starting_joker_count`, если он
  известен. Отсутствие поля означает неизвестность, а не ноль занятых слотов.
- Схема сохранения 7, ревизия API 1.1.0 и формат истории 2 — разные номера.
  Обязательная миграция и добровольное дополнение каталога требуют отдельных
  решений игрока; провайдер не должен напрямую переписывать его серию.

Если интеграция требует новых возможностей, укажите зависимость
`Showstreak (>=1.3.0)` и проверьте нужную capability. Полный учебный пример ниже
использует прежний поддерживаемый контракт с минимальной зависимостью 1.1.0.

## 1. Выберите подходящее расширение

Showstreak связывает забеги в серию со своим магазином, правилами, Кастингом,
условиями и Шоуменом. Интеграция описывает контент для этих систем, а при
необходимости предоставляет версионированный обработчик начала забега. Она
не заменяет исходный мод Balatro, который реализует вашу колоду, рукав,
партнёра или другой игровой объект.

Начните с самого простого публичного механизма, подходящего для идеи:

| Идея | Механизм |
| --- | --- |
| Дополнительная рука в следующем забеге | Предмет `prop`, эффект `hands` |
| Дополнительные стартовые деньги до Антракта | Ваучер с `money` |
| Более трудный забег за награду при победе | Контракт |
| Раскрытие условия или заданная следующая колода | Поддерживаемый трюк |
| Выбор предметов в инвентарь | Пак из пула `props` или `tricks` |
| Ваучеры или смешанные награды | Пак версии 2: `vouchers` / `mixed` |
| Накапливаемое условие акта | Условие/маска |
| Особое действие на старте забега | Зарегистрированный custom effect |
| Новая категория выбора перед забегом | Стартовое дополнение |
| Запрет игрового объекта | Дополнительный источник бана |
| Ограничение действий или расписания боссов | Источник action policy |
| Ситуативная реплика и эмоция | Реакция Шоумена |

Для обычного изменения ресурса выбирайте встроенный эффект. Его предпросмотр,
границы, срок действия и сохранение уже связаны с остальными системами.
Собственный обработчик нужен для особого поведения, а не просто как другой
способ добавить два доллара.

Руководство опирается на [исходники ShowstreakExample](examples/integration/README.md).
В нём нет файлов изображений: пример обращается к ресурсам установленной игры.
Он добавляет игровой контент и меняет каталог будущих серий. Проверяйте его
в отдельном тестовом профиле. Точные поля и числовые ограничения собраны
в [API.md](API.md); это подробный справочник на английском языке.

Пример предоставлен для обучения и локальных проверок по существующим условиям
автора. Ваша самостоятельно написанная интеграция распространяется отдельным
модом с зависимостью от Showstreak. Границы распространения описаны в главе 18.

## 2. Установите локальный пример

Оставьте Showstreak 1.3.0 установленным обычным способом. В репозитории пример
намеренно хранится с неисполняемым суффиксом `.example`. Создайте отдельную папку
`Mods/ShowstreakExample`, скопируйте туда [манифест](examples/integration/ShowstreakExample.json.example)
и [Lua-исходник](examples/integration/main.lua.example), затем уберите только
последний суффикс `.example` у обоих файлов. Получится:

```text
Mods/
  Showstreak/
    Showstreak.json
    main.lua
  ShowstreakExample/
    ShowstreakExample.json
    main.lua
```

Не помещайте пример внутрь рабочей папки Showstreak. Весь Toolkit в Mods
копировать тоже не нужно: руководства не являются ещё одной установкой мода.
Перезапустите игру, чтобы SMODS обнаружил манифест и новые объявления.

В манифесте указаны ID `ShowstreakExample`, префикс `ssex`, приоритет `0`
и зависимость `Showstreak (>=1.1.0)`. Зависимость не позволяет примеру выдавать
старую ревизию API за подходящую. Ранний приоритет специально проверяет
инициализацию через hook, а не требует ручной перестановки модов.

Создайте новую тестовую серию и проверьте каталог и настройки. Репетиционная
колода даёт два дополнительных стартовых доллара. «Стартовый билет» — новая
категория дополнений: включите её в собственных правилах, чтобы получить
пять вариантов перед забегом. Во встроенных режимах она выключена.

Магазин Showstreak зависит от сида: предмет примера не обязан появиться сразу
в первом магазине. Наличие регистрации можно проверить по ID через API,
независимо от случайного предложения.

Источник бана из примера запрещает обычного джокера Credit Card в Showstreak.
Это намеренная демонстрация объединения запретов. После знакомства уберите
папку примера, если не хотите его контент в будущих сериях. Уже созданная
тестовая серия, которой он необходим, сообщит об отсутствующем провайдере.
Начните новую обычную серию; не исправляйте это удалением полей сохранения.

## 3. Создайте манифест и точку инициализации

До публикации выберите постоянный ID мода. Showstreak использует его для
принадлежности контента, пространства имён и совместимости. Отображаемое
название можно менять, не переименовывая эти идентификаторы.

```json
{
  "id": "MyStageMod",
  "name": "My Stage Mod",
  "author": ["Your name"],
  "prefix": "myst",
  "main_file": "main.lua",
  "version": "1.0.0",
  "priority": 0,
  "dependencies": ["Showstreak (>=1.1.0)"]
}
```

Сначала создайте собственные объекты SMODS. Адаптер колоды должен ссылаться
на уже зарегистрированный `SMODS.Back`, а предмет с вашим атласом — на уже
зарегистрированный атлас. Затем задайте `showstreak_init` у объекта своего мода:

```lua
local mod = assert(SMODS.current_mod)
mod.showstreak_init = function(api)
    assert(api.version == 1, 'Unsupported Showstreak API')
    assert(api.get_api_info().capabilities.conditions == 1)
    -- Здесь: api.register_item, api.register_condition и другие.
end
if Showstreak and Showstreak.api and Showstreak.api.ready then
    assert(Showstreak.initialize_integration(mod.id))
end
```

При ранней загрузке Showstreak сам найдёт функцию после подготовки всех API.
При поздней загрузке условие в конце вызывает тот же однократный путь хоста.
Не вызывайте `mod.showstreak_init()` напрямую и не дублируйте регистрации вне
него. После `SMODS.booted` регистрация закрыта.

Вызывайте функции фасада через точку. Фасад подставляет вашего провайдера,
не меняя глобально текущий мод SMODS. Полный пример использует этот же шаблон
и проверяется при обоих порядках загрузки. Ошибка hook останавливает загрузку
с диагностикой провайдера. Исправьте определение и перезапустите игру: частично
успешные регистрации из упавшей функции не являются откатываемой транзакцией.

## 4. Разбирайте ошибки и сохраняйте ID

Моду `MyStageMod` принадлежат ID с началом `mystagemod_`. Его префикс SMODS
`myst` — отдельная вещь: игровая колода может называться `b_myst_reserve`,
а предмет Showstreak — `mystagemod_spare_hand`. Приведите ID провайдера
к нижнему регистру, замените пунктуацию подчёркиваниями и добавьте `_`.
Не используйте пространство имён чужого мода.

При успехе регистрация возвращает ID или ключ. При ошибке — nil, короткий код
и структуру с подробностями. Код подходит для программной проверки, сообщение
помогает человеку исправить конкретное поле.

```lua
local result, code, detail = api.register_item(definition)
if not result then
    error(tostring(code) .. ': '
        .. tostring(detail and detail.message))
end
```

Это иллюстрация обработки ошибки: `definition` должен содержать настоящее полное
определение. В main.lua примера есть общий помощник с таким поведением.
`api.get_api_error()` возвращает копию последней диагностики: operation, code,
field, provider и id, когда они известны. Успешная регистрация очищает её.
Старые интеграции, читающие только два возвращаемых значения, продолжают работать.

Не обходите ошибку изменением `Showstreak.content`, реестров `Showstreak.api`
или каталога сохранённой серии. Обычное определение состоит из конечных чисел,
строк, boolean и простых таблиц без циклов. Функция допустима только в явно
разрешённом callback-поле. Разреженный массив уровней не считается обычным списком.

Сохраняйте опубликованные ID, даже если улучшаете названия и переводы.
Не отдавайте старый ID совершенно другому эффекту. `content_version` — метаданные
предмета или условия, а не исполняемая миграция. Версии обработчиков и стартовых
дополнений имеют более строгие последствия для загрузки; об этом глава 15.

В начале полезно проверить `get_api_info().registration_open`, нужные capabilities
и наличие игрового центра или атласа. Это помогает моддеру, но не означает,
что названия внутренних полей должны попадать в обычные описания для игрока.

## 5. Создайте предмет и его описание

Предмет `prop` после покупки или выбора попадает в инвентарь. Затем игрок
нажимает «Использовать», чтобы подготовить эффект к следующему забегу.
Покупка сама по себе не меняет текущий игровой забег. Отразите этот момент
в описании.

Ниже полная регистрация внутри hook провайдера из примера. Для собственного
мода замените префикс ID на производный от своего провайдера.

<!-- sdk-check: hook -->
```lua
assert(api.register_item {
    id = 'showstreakexample_guide_hand',
    kind = 'prop', effect = 'hands', value = 1,
    price = 2, art = 'j_joker', content_version = 1,
    loc_txt = {
        ['en-us'] = {
            name = 'Spare Hand',
            text = {'{C:blue}+#1#{} hand each round',
                'during the {C:attention}next run{}'},
        },
        ru = {
            name = 'Запасная рука',
            text = {'{C:blue}+#1#{} рука каждый раунд',
                'в {C:attention}следующем забеге{}'},
        },
    },
})
```

Цена выражена в золотых звёздах, а не долларах обычного забега. `value` для
ресурсного эффекта — целочисленное изменение. В нативном описании `#1#`
показывает его величину; цветная разметка здесь допустима. `art='j_joker'`
ссылается на рисунок существующего центра. Хост создаёт специальный центр
Showstreak, исключённый из обычного пула джокеров.

Ресурсные эффекты охватывают стартовые деньги, руки, сбросы, размер руки,
слоты джокеров и расходников, размер колоды и слоты магазина. `blind`, `boss`,
`prices` используют дробные изменения: `0.15` означает +15%, а не множитель 15.
Вклады в один модификатор складываются. Проверяйте ограничения и цену на
крайних разрешённых значениях и вместе с другими эффектами: валидация не
оценивает игровой баланс.

Сверьте эффект с информацией о следующем забеге, затем запустите сам забег
и загрузите его сохранение. Предмет не должен выдать бонус повторно.

## 6. Ваучеры, контракты, трюки и паки

Выбирайте тип по действию игрока и сроку эффекта, а не по желаемому рисунку.
Хост назначает способ активации и визуальное семейство на основе типа.

| Тип | Действие игрока | Что остаётся |
| --- | --- | --- |
| Ваучер | Покупка | Бонус между забегами до Антракта/конца |
| Контракт | Бесплатное принятие | Изменение следующего забега и награда |
| Трюк | Получение, затем использование | Немедленное поддерживаемое действие |
| Пак | Открытие и выбор | Предметы/трюки в инвентаре; ваучеры/пари версии 2 применяются сразу |

Паки версии 2 также выдают ваучеры и пари: они применяются сразу после выбора,
а не попадают в инвентарь. Следующий выбор проверяет условия, конфликты пари и
вместимость заново. Заблокированная карточка не тратит выбор; дополнительная
оплата звёздами за выбор не требуется.

«Бюджет сцены» из примера — ваучер с дополнительными $2 на старте.
«Короткий номер» — бесплатный контракт: на одну руку меньше, ещё две звезды
за победу. Его описание не должно обещать награду за одно только принятие.
«Билет на репетицию» использует `set_deck` для следующего забега; целевая
колода должна быть разрешена в этой серии.

Ваучеры поддерживают обычные эффекты забега и дополнительные `reward`,
`held_slots`, `free_reroll`, `reveal_act`. Поле `requires` указывает ранее
зарегистрированный ваучер. Сначала зарегистрируйте предшественника, затем
улучшение и проверьте суммарное описание цепочки. Не заменяйте зависимость
проверкой текущих покупок в момент загрузки мода.

«Чемодан за кулисами» предлагает три варианта из `props`, выбрать один.
Этот пул включает подходящие предметы и трюки. Пул `tricks` содержит только
трюки. Число предложений — от 1 до 5, выбор не может превышать его.
API не предоставляет произвольный генератор паков или новые категории магазина.

В 1.3.0 для `vouchers` и `mixed` укажите `pack_version=2` и проверьте
`capabilities.pack_pools >= 2`. Версия 2 допускает один или два выбора
(для ваучеров — ровно один), устанавливает предел расширения до шести предложений
и поддерживает Prop Master без увеличения числа взятых карт. Смешанный пак
гарантирует платный вариант или совместимую платную пару, а не только бесплатные
пари. Открытые варианты сохраняются при загрузке. Пример регистрации находится
в [приложении API](API_130.md#pack-pools-capability-2).

Веса — целые числа 1–100. Семейство с собственным ID группирует связанные
варианты перед выбором участника: много однотипных билетов не обязаны заполнять
весь магазин. Все участники должны иметь одинаковый `family_weight`.
Семейство влияет на частоту выбора, а не на владение, срок или зависимости.

Фиксированные значения трюков и допустимые дополнительные поля перечислены
в API.md. Callback нельзя спрятать в обычном определении трюка. Если особое
действие относится к старту забега, используйте зарегистрированный эффект.

## 7. Опишите настоящую игровую колоду

Адаптер не создаёт игровую колоду. В примере сначала объявлен `SMODS.Back`
с ключом `rehearsal`, нативным рисунком и `config.dollars=2`. Steamodded
присваивает ему ключ `b_ssex_rehearsal`. Затем hook регистрирует именно этот
ключ в Showstreak и указывает полный набор стартовых ресурсов.

```lua
-- Базовые значения примера: обычный старт плюс $2 от колоды.
baseline = {
    money = 6, hands = 4, discards = 3, hand_size = 8,
    joker_slots = 5, consumable_slots = 2, deck_size = 52,
    shop_slots = 2, booster_slots = 2,
}
```

Нужны все девять полей. Деньги могут быть отрицательными в указанных пределах;
остальные ресурсы — неотрицательные целые числа. Не добавляйте Ante, ресурсы
текущего раунда или уже потраченные игроком значения.

Статическая таблица описывает колоду при заводских стартах до эффектов ставки.
Разницу от пользовательских правил Showstreak добавляет сам. Если колода даёт
две дополнительные руки, заводское `hands` равно 6. При изменении базовых рук
с 4 до 7 предпросмотр должен показать 9, а не оставаться 6 и не превращаться в 11.

Если старт зависит от окончательных правил, передайте чистую детерминированную
функцию `baseline(rules_copy)`. Она возвращает уже итоговые значения до ставки
и сама учитывает пользовательский старт. Не добавляйте статическую поправку
ещё раз. Предпросмотр может вызывать функцию многократно: здесь нельзя тасовать
карты, тратить RNG или выдавать ресурсы.

Сначала проверьте колоду в обычном Balatro, затем в серии с заводскими
и изменёнными стартами, разными ставками и трюком смены колоды. Адаптер помогает
предпросмотру и проверке ограничений, но не доказывает правильность всех хуков
сложной колоды. При несовместимом изменении контракта baseline увеличьте версию
адаптера. Для старой серии её обязательный провайдер должен оставаться доступен.

## 8. Зарегистрируйте условия и раскрытия Кастинга

Условие подключается к существующей системе масок и актов. Вы задаёте категорию,
эффект и упорядоченные уровни. Предложения, видимость, выбор, накопление,
удаление и сброс выполняет хост. `register_mask` обращается к той же регистрации.

<!-- sdk-check: hook -->
```lua
assert(api.register_condition {
    id = 'showstreakexample_guide_toll', category = 'economy',
    effect = 'money', values = {-1, -2, -3}, minimum = 0,
    loc_txt = {
        ['en-us'] = {name = 'Stage Toll',
            text = {'Start runs with $#2# less'}},
        ru = {name = 'Плата за сцену',
            text = {'На старте на $#2# меньше'}},
    },
})
```

Здесь используется обычный money. «Налог на чаевые» в полном примере обращается
к собственному Lucky Tip. Категории: `economy`, `blinds`, `resources`.
`values` — плотный массив из 1–16 ненулевых уровней. `minimum` задаёт ресурсную
границу допуска, а не callback. Временные условия используют первый уровень.
Более высокие уровни доступны с продвижением локальных актов и с учётом
остальных проверок системы.

Условия `ban_jokers`, `ban_consumables`, `ban_vouchers`, `ban_packs` работают
при включённом Кастинге. Обычные ресурсные условия сохраняют стандартное
поведение. Не добавляйте определения напрямую в таблицу запущенной серии:
новые регистрации относятся к каталогам новых серий.

Ваучер раскрытия Кастинга использует `effect='casting_reveal'`, `value=6`,
чтобы показать шестое предложение. Допустимы позиции 2–7; первая уже открыта.
Ваучер не выбирает джокера за игрока и не добавляет ещё один выбор: игрок
по-прежнему выбирает три карты из семи. «Шестой прожектор» показывает именно
такую фиксированную позицию.

Как любой ваучер, он исчезает при принятом Антракте. Не сохраняйте рядом
постоянный флаг, который тайно оставит карту открытой после сброса.
Проверьте покупку, следующий Кастинг, сохранение/загрузку и принятие Антракта.

## 9. Определите собственный эффект забега

Lucky Tip показывает поведение, отличающееся от фиксированного money:
активная величина умножается на детерминированное число от одного до трёх.
Предпросмотр и выдача денег используют одинаковый независимый поток RNG.

Сначала зарегистрируйте обработчик, затем ссылайтесь на его ID в предметах
и условиях. Ниже полная минимальная регистрация для провайдера примера.
Счётчик здесь иллюстрирует контракт; исполняемый SDK меняет видимые доллары.

<!-- sdk-check: hook -->
```lua
assert(api.register_effect {
    id = 'showstreakexample_guide_tokens', version = 1,
    kinds = {prop = true, voucher = true, contract = true},
    conditions = true,
    value = {min = -20, max = 20, integer = true},
    loc_txt = {
        ['en-us'] = {name = 'Admission Tokens', text = {'#1# tokens'}},
        ru = {name = 'Входные жетоны', text = {'#1# жетонов'}},
    },
    apply = function(value, context)
        context.game.example_tokens = value
        return {tokens = value}
    end,
})
```

Обработчик разрешает типы предметов и/или условия. `value` ограничивает отдельное
определение, а не сумму активных вкладов. Showstreak складывает их по ID эффекта
и вызывает callback один раз с итогом. При нулевой сумме вызова нет. Несколько
обработчиков выполняются по сортированным ID; не делайте корректность зависимой
от выбранного чужим провайдером имени.

`version` — точный контракт поведения и сохранённого состояния. Код остаётся
у загруженного провайдера; в каталог попадают только метаданные. Функции
никогда не записываются в сохранение. Предмет запоминает провайдера и версию
обработчика при регистрации, поэтому позднее объявление эффекта не исправляет
уже отклонённый предмет.

Свои обработчики поддерживают props, vouchers, contracts и conditions.
Они не создают произвольные мгновенные трюки, генераторы собственных пулов или общий
движок миграции сохранений. Более широкие нативные возможности ваш мод
реализует собственными хуками SMODS и сам сохраняет их совместимость
с этим конкретным контрактом старта и восстановления.

## 10. Согласуйте предпросмотр и сохранения

Контекст эффекта содержит `series_id`, `run_id`, `seed`, `locale`, копию `rules`,
`phase`, непрозрачный токен операции `token` и `random(upper)`. Apply/resume
дополнительно получают живой `game`. Предпросмотру не передаются game, скрытая
маска, объект кампании или будущие предложения.

Для воспроизводимого выбора используйте `context.random(upper)`. Предпросмотр
начинает поток с того же исходного сида, что и apply, не расходуя RNG серии
или обычной игры. Одинаковые вызовы в одинаковом порядке дают одинаковый
результат. Повторный предпросмотр не должен выдавать ресурсы, писать файлы,
менять регистрации или сдвигать собственный глобальный случайный счётчик.
В SDK показанные чаевые совпадают с фактическим изменением стартовых денег.

`apply` возвращает nil или простую таблицу состояния. Сохраните нужные факты,
например полученную сумму; не сохраняйте карты, game, функции или циклы.
Хост связывает запись с токеном, величиной и версией эффекта, сохраняет контрольную
точку до применения и после успеха. Завершённый эффект не выдаёт бонус заново
при продолжении нативного сохранения.

Необязательный `resume(value, context, state_copy)` восстанавливает временные
наблюдатели или интерфейсные ссылки. Не повторяйте выдачу: игрок мог уже
потратить деньги. Верните nil/true при успехе; false или исключение означают
ошибку. У восстановленного объекта игры не больше одного resume-вызова
для этого завершённого эффекта.

Если раннее сохранение сделано до первого apply, ожидающая операция может
завершиться после загрузки. Уже начатая незавершённая или упавшая операция
блокируется: хост не угадывает, какие побочные действия успели произойти.
Нативная запись асинхронна; отправленная контрольная точка не равна подтверждённой
записи на диск или транзакции с внешним сервисом. Своей внешней операции,
требующей однократности, также передавайте стабильный токен.

Установленные Lua-моды — доверенный код. Копия контекста задаёт интерфейс,
но не является песочницей, запрещающей доступ к глобальным объектам.
За инварианты игры и отсутствие посторонних действий в preview отвечает провайдер.

## 11. Добавляйте запреты без отмены чужих правил

Источник бана добавляет запрет. Он не получает последнего слова, позволяющего
объект, запрещённый другим источником. Так совместно работают Banner,
закрытые джокеры Кастинга, условия и ваша интеграция.

<!-- sdk-check: hook -->
```lua
assert(api.register_ban_source {
    id = 'showstreakexample_guide_cash_only', version = 1,
    is_banned = function(key, context)
        return key == 'j_credit_card'
    end,
})
local result = api.query_object_ban('j_credit_card')
assert(result.banned)
```

Для постоянного списка замените `is_banned` на `keys={j_credit_card=true}`.
Разрешена ровно одна форма. Контекст предиката содержит публичные ID серии
и забега, фазу и копию правил. На каждом пути возвращайте boolean.
Отсутствующий return — не false: это ошибка предиката, запрещающая данный объект.

`query_object_ban` возвращает ключ, boolean и массив причин. Причина указывает
на Banner, ваш источник, внешний нативный запрет, Кастинг или условие.
Используйте это в своих инструментах для объяснения доступности. Прямое
редактирование `G.GAME.banned_keys` не заменяет контракт интеграции.

При смене настроек Banner может пересоздать свою нативную таблицу. Адаптер
Showstreak после этого повторно применяет собственные запреты снимка забега.
Удаление причины Banner не удаляет чужую причину. Рекурсивный запрос из
предиката к собственному источнику отклоняется, чтобы не образовался цикл.

Хост фильтрует поддерживаемые способы получения и сохраняет уже имеющиеся карты.
Чужой мод с отдельным прямым созданием объектов всё равно требует проверки
в игре. Значок интеграции не доказывает покрытие всех посторонних хуков.

Сохраняйте провайдера и версию источника для запущенной серии. Отсутствующий
обязательный источник или несовместимая версия должны дать объяснимую ошибку,
а не молча ослабить правила. Значение false означает лишь, что конкретный
источник сейчас не запрещает объект; оно не является глобальным разрешением.

## 12. Предложите новую стартовую категорию

`register_start_addon` подходит для контента, выбираемого перед забегом:
талисманов, билетов или стартового спутника из другого мода. У Sleeves и Partner
уже есть собственные адаптеры. Не занимайте их ключи и не заменяйте callbacks.

SDK регистрирует `showstreakexample_pocket`, видимый игроку как «Стартовый билет».
Во встроенных правилах категория выключена. При включении каждый забег получает
пять вариантов: медный, серебряный, золотой, бархатный билет и билет на бис,
дающие от одного до пяти стартовых долларов. Это намеренно простой проверочный
каталог, а не пример пяти одинаково сбалансированных альтернатив.

Нужны функции `available`, `catalog`, `display`, `apply`, необязательный `resume`,
обязательная целочисленная версия контракта, локализованные `name` и `description`.
Локализация дополнения использует строки или язык → строка, а не нативный
формат карточки `{name,text}`.

Для категории 1.3.0 можно указать `starting_joker_count` — консервативный максимум
занимаемых на старте слотов джокеров, целое 0–999. Ноль явно означает отсутствие
начальных джокеров, пропуск поля — неизвестность. Blue Skittles и Red Brain
нуждаются в этой гарантии для выбранной категории. В базовом учебном примере
поле пропущено: для такой проверки выбирайте «Нет» либо создайте версионированную
категорию 1.3.0 с нулём для денежного бонуса. Новое объявление не дополняет
метаданные старой сохранённой серии.

`catalog(context)` возвращает плотный массив максимум из 512 записей с `key`,
необязательными `data` и нативным `center`. Ключи уникальны, значение `none`
зарезервировано. В data помещаются только простые сериализуемые сведения.
Пример сохраняет английские/русские названия и суммы, а `j_joker` использует
как нативное изображение предпросмотра.

`display(entry_copy, context)` возвращает имя и необязательное описание.
Функция чистая и может вызываться многократно. В результате не нужны карты,
callbacks или дерево узлов UI. Рисунок берётся из `center` сохранённой записи.
При наличии центра бан проверяется по нему, иначе — по ключу записи.

Контекст дополнения содержит `campaign_id`, `run_id`, `deck`, `stake`, `seed`,
копию `rules` и `language`. Эти названия отличаются от `series_id` и `locale`
в контексте custom effect. Следуйте контракту конкретной функции: общий
помощник, ошибочно ожидающий одинаковые поля во всех callbacks, может
незаметно показать неверный язык или потерять идентификатор серии.

## 13. Сохраняйте стартовый выбор игрока

Хост фиксирует каталог включённого дополнения при создании серии. Для каждого
следующего забега он выбирает до пяти разных подходящих записей и сохраняет
предложения. Игрок выбирает одну или явный вариант «Нет». Маленький пул даёт
меньше вариантов; пустой доступный пул завершается без дополнения. Перезагрузка
не должна перетасовывать выбор или автоматически выбирать лучший билет.

Не нужно делать параллельный редактор настроек или свой случайный выбор для
повторения этого поведения. Зарегистрируйте категорию: Showstreak покажет её
переключатель перед серией и окно выбора перед забегом. Флаг называется
`rules.start_addons[addon_id]` и фиксируется после старта серии, включая Антракт.
Новые живые записи не попадают в её старый сохранённый каталог.

`apply(entry, context)` выполняется через очередь событий после нативной
подготовки. Он получает подтверждённую запись, живой game, токен и
`phase='start'`. Nil/true означают успех, false или ошибка не позволяют молча
продолжить неполный запуск. До вызова хост сохраняет статус `applying`, после
успеха отмечает `applied` и снова сохраняет.

Ожидающая операция из сохранения может впервые примениться при загрузке.
Уже применённая получает только необязательный `resume(entry, context)`
с `phase='resume'`. Восстанавливайте временные наблюдатели, а не бонус.
Прерванную запись applying/failed нельзя безопасно считать завершённой:
она блокируется. Ограничение асинхронных нативных сохранений здесь такое же,
как у custom effects.

Недоступный провайдер, другая версия или отсутствующий обязательный центр
дают объяснение при продолжении. Не возвращайте другой каталог, скрывая
пропажу сохранённого контента. Для внешних ресурсов используйте токен
однократности и сохраняйте обычный подтверждённый выбор игрока.

Проверьте ожидающую контрольную точку, завершённое сохранение после траты
ресурсов и повторное восстановление. В SDK стартовые доллары не увеличиваются
заново при продолжении.

## 14. Дайте Шоумену точные и разнообразные реплики

Реакция Шоумена — данные для подтверждённого публичного события. Пример
`showstreakexample_spare_hand_bought` совпадает с `event='buy'`, точным ID
предмета и `source='buy'`. Он не утверждает, что предмет уже использован.

Через `api.get_showman_info()` можно узнать текущие события, поля сравнения,
подстановки, эмоции и манеры речи. Набор фактов зависит от события.
Сравнение поддерживает точные строки, boolean и конечные числа; callbacks
и просмотр скрытой маски не входят в механизм выбора реплик.

Для языка задаются 1–4 обычные строки, максимум 140 Unicode-символов суммарно
до подстановок. Обязателен запасной `text['en-us']`. Фигурные скобки и переносы
внутри строки запрещены: это речь, а не цветная карточная подсказка.
Подстановки `#value#`, `#item_name#` ссылаются на открытые факты.
Отсутствующее поле превращается в `?`; проверяйте настоящее событие,
а не только искусственно заполненный предпросмотр.

Добавьте несколько разных реакций на ситуацию. `family` и `topic` помогают
избегать повторов. Приоритет — 1–90, по умолчанию 50; если всем выставить 90,
тайминг не станет лучше. `once=true` запоминает видимый выбор реплики в профиле,
а не создаёт игровой флаг «раз за забег».

`presentation` задаёт эмоцию, направление взгляда и манеру речи. В примере
это playful/center/bright. Алиасы используют существующие рисунки и не означают
дополнительные кадры. API карты спрайтов нужен только для собственного
подготовленного рисунка, а не для автоматического дорисовывания.

Добавьте `compact_text`, если длинный перевод или имя могут не поместиться.
Сократите фразу с сохранением смысла. Через
`api.preview_showman_reaction(id, data)` проверяются текст, укладка и эмоция
без произнесения и расхода игрового RNG. Затем посмотрите настоящий пузырь
в игровом масштабе.

Для своего завершённого действия зарегистрируйте `MyStageMod:encore`
и отправьте это событие после успеха. Это запрос реплики: настройки игрока,
сцена и контроль повторов могут оставить Шоумена молчать. Реплика не является
подтверждением того, что игровое действие выполнилось.

## 15. Учитывайте фиксированный каталог и Антракт

Серия — сохранённое соглашение о правилах и каталоге. Регистрация влияет
на новые серии. У существующей сохраняются собственные определения предметов
и условий, порядок, baselines и необходимые метаданные расширений.
Исполняемые callbacks провайдера в сохранение не записываются.

Обязательное обновление до схемы сохранения 7 показывает изменения и проверяет
резервную копию. Отдельное **Правила → Добавить новый контент** между забегами
добавляет отсутствующие совместимые ID. Прежние определения, правила и предложения
сохраняются, кроме явно показанных изменений совместимости. Новый каталог может
изменить будущие случайные предложения. Провайдер не должен обходить решения игрока.

| Изменение | Что произойдёт со старой серией |
| --- | --- |
| Добавлен предмет или условие | Войдёт только после принятого совместимого обновления каталога |
| Улучшен доступный перевод | Текст может обновиться без нового эффекта |
| ID убран из живого каталога, провайдер сохранён | Описание восстановится из снимка |
| Удалён обязательный код провайдера | Продолжение объяснит его отсутствие |
| Несовместимая версия эффекта/дополнения | Продолжение сообщит о несовместимости |
| Принят Антракт | Сработает обычный сброс предметов и условий |

`content_version` не запускает миграцию. Общая версия мода полезна в диагностике,
а у адаптера колоды, источника бана, эффекта и дополнения есть свои проверки
контракта. Не оставляйте старую версию custom effect при радикальном изменении
формата callback-state. Автоматического миграционного callback для произвольных
изменений нет.

Антракт сохраняет ID серии, общий винстрик, тёмные звёзды профиля, историю
начислений и фиксированные правила/каталог. Он очищает инвентарь, ваучеры,
условия и подготовленные эффекты следующего забега, возвращает локальную
прогрессию и золотые звёзды к соответствующему старту. У нового отрезка
будет новый детерминированный сид.

Раскрытие Кастинга — ваучер, поэтому сбрасывается. Эффекты ваших ваучеров
и условий подчиняются тому же сроку. Стартовая категория остаётся включённым
правилом, но следующий забег получает обычный новый выбор и новый токен.
Не храните отдельное постоянное улучшение, обходящее Антракт.

Допуск к тёмным звёздам определяет экран настройки. Иностранный игровой
контент каталога и включённые стартовые дополнения не дают встроенные награды.
Одни только косметические реплики и источники бана не отключают их
автоматически. Не обещайте награду независимо от фактической проверки хоста.

## 16. Пишите локализацию для игрока

Дайте понятное имя и опишите действие, момент и величину. «На старте ещё $2
до Антракта» объясняет пользу. «Устанавливает поле money и сохраняет
модификатор серии» уместно в руководстве, но не на ваучере.

| Поверхность | Формат данных |
| --- | --- |
| Предмет или условие | Нативные name/text в `loc_txt` |
| Custom effect | `loc_txt`, необязательное чистое preview-описание |
| Стартовая категория | Обычные локализованные name/description |
| Стартовый вариант | Локализованные имя/описание из display |
| Шоумен | Обычные строки, эмоция, манера, сокращённый вариант |

Используйте точные языковые ключи, например `en-us` и `ru`, и английский
запасной текст. Подбор регионального/базового языка помогает при отсутствии
варианта, но одинаковые английские строки под всеми ключами не считаются
полным переводом. В SDK все видимые поверхности действительно переведены
на английский и русский.

В описаниях карт сохраняйте `#1#`, `#2#`, `#3#` и разметку `{C:...}`.
У предмета `#1#` — величина, `#2#` — награда или число выбираемых карт пака,
`#3#` — суммарная величина цепочки ваучеров. У условия `#2#` — абсолютная
величина уровня. Запасной preview custom effect заменяет `#1#` итоговой суммой.
Не предполагайте, что один номер имеет одинаковый смысл везде.

В речи сохраняйте именованные подстановки и лимит исходного текста.
Переведённые имена могут оказаться длиннее. Проверьте самое длинное имя
карты/колоды, максимальное число, узкий пузырь и compact fallback.
Используйте результат проверки укладки, затем оцените отрисовку в игре:
ширина шрифта не равна числу символов.

Локализация должна оставаться сериализуемой: сохранённый предмет или убранное
из живого каталога условие сохранят осмысленный текст. Запасной рисунок
не восстановит код отсутствующего провайдера, а хорошая подсказка не сделает
несовместимый callback безопасным. Переводите пользовательские объяснения
ошибок, сохраняя подробности провайдера/поля в диагностике для разработчика.

## 17. Проверяйте правильный уровень поведения

Автоматическая проверка комплекта загружает рабочие модули Showstreak через
LuaJIT самой игры. Она проверяет оба порядка загрузки SDK и выполняет полные
помеченные регистрации из руководств. Нативные SMODS-объекты представлены
небольшим стендом: это проверка контракта, а не доказательство отрисовки в игре.

Ожидаемые результаты для полного примера:

| Проверка | Результат |
| --- | --- |
| Репетиционная колода | Нативные +$2, baseline money 6 при обычном старте |
| Запасная рука | Инвентарь после покупки, +1 рука после использования |
| Бюджет сцены | +$2 на стартах, обычный сброс Антрактом |
| Короткий номер | -1 рука, дополнительные звёзды только за победу |
| Чемодан за кулисами | Три подходящих предложения, один выбор |
| Шестой прожектор | Открыта именно шестая карта Кастинга |
| Счастливые чаевые | Предпросмотр совпадает с фактическими деньгами |
| Стартовый билет | Пять предложений, выбранная выдача один раз |
| Источник Cash Only | Credit Card запрещён при чужом разрешении |
| Реплика Шоумена | Событие покупки и правильная эмоция |

В Balatro пройдите покупку, использование, старт и продолжение. Сохранитесь
после траты части выданных денег: после загрузки они должны остаться потраченными.
Примите Антракт и проверьте сбросы. Добавьте такой же бан в Banner, затем
уберите его и убедитесь, что источник SDK по-прежнему запрещает объект.
Отдельно проверьте Banner в обычном Balatro, чтобы адаптер не нарушал его
исходное поведение.

Проверки отсутствующего провайдера и изменённой версии выполняйте на ненужных
тестовых сохранениях. Ожидается объяснимый отказ, а не повторный бонус или
подмена каталога. Посмотрите оба языка и фокус контроллера в настоящем меню.
Не редактируйте рабочее сохранение игрока ради нужного предложения для скриншота.

Разделяйте тесты чистой логики и приёмку игровых хуков. Успех одного уровня
не обещает совместимость с любым набором модов, платформой, шрифтом,
настройкой звука или библиотекой больших чисел.

## 18. Подготовьте выпуск и дальнейшую поддержку

Распространяйте самостоятельно написанную интеграцию отдельным модом
со стабильными ID, своим манифестом и зависимостью от Showstreak. Включайте
свои файлы и их лицензии. Обращение к рисункам установленной игры подчиняется
условиям владельцев этих рисунков; API не выдаёт на них новых прав.

Не вкладывайте в свой распространяемый мод runtime Showstreak, авторские
спрайты, поставленные руководства, исходник примера или данные игрока.
Пример разрешён для обучения и локальных проверок, а не автоматически для
перепубликации. Для распространения предоставленных файлов нужно отдельное
разрешение автора. [LICENSE](../LICENSE) сохраняет существующие ограниченные
условия использования; это не open-source лицензия.

Перед обновлением перечислите изменившиеся контракты. Исправление перевода
обычно не требует новой версии эффекта. Изменённый формат или смысл состояния
callback требует честной смены версии. Сохраняйте обязательного провайдера,
если старые серии должны продолжаться; не удаляйте все его регистрации только
потому, что новый магазин больше не предлагает прежний предмет.

`provider_manifest`, `mod_report` и `environment_report` помогают разбирать
сообщения об ошибке. Значок интеграции означает регистрацию поддерживаемого
контента, а не сертификацию всех чужих хуков. Для воспроизводимого отчёта нужны
версии игры/загрузчиков/провайдеров, точное действие и код диагностики.
Для обычной API-ошибки не требуются посторонние личные файлы игрока.

В комплекте три взаимодополняющих документа: этот порядок работы, английский
вариант и точный справочник API. Устанавливаемый пример — проверенная полная
программа. Короткие непомеченные схемы показывают поля, но не являются целыми
модами. Проверки собственной интеграции должны соответствовать версии
Showstreak, объявленной в зависимости.

Полезная последняя проверка выпуска: игрок читает предмет, понимает момент
действия, выбирает его, начинает забег, сохраняется, возвращается и получает
ровно обещанное поведение. Работа с API нужна, чтобы этот обычный игровой путь
оставался надёжным.
